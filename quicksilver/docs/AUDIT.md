## How to read the numbers

A result is described by separate categories that are never averaged into one. Each has one definition (`src/core/metrics.js`):

* **identification**: The detector names the tool with confidence >= 0.5 on the obfuscated fixture (and, where the fixture records a version, the version it reads equals it). Reported as detected / fixtures.
* **structure**: structureScore(original, recovered): F1 of the multiset of parent>child node-type edges of the two syntax trees; names, literal values, comments, parentheses and sibling order are ignored. 1.0 = the same shape of program. Mean over fixtures whose output parses.
* **semantic**: fidelity(original, recovered): Dice coefficient of the longest common subsequence of the semantic-token streams (node kinds, operators, literal values, locals by order of declaration, globals by name), over the first 6000 tokens of each. Mean over fixtures whose output parses.
* **runtime**: The recovered script and the original program are run on the same real runtime (PUC Lua 5.1 / LuaJIT / Lua 5.4 through lupa, or Luau 0.739) and their captured output compared. Counted only where the obfuscator’s own output behaved like the original, so a tool defect is never charged to the engine. same / judged.
* **completeness**: Both of: residualIndicators(recovered) is empty (the detector finds in the recovered text no tool with unrecoverable evidence, none of the traits state-machine, bytecode-blob, string-table, junk-code, opaque-predicates, escape-encoded-strings, and no virtual machine’s function records and interpreter), and the engine’s own report lists nothing left unresolved. complete / fixtures.
* **vmConstants**: Only for builds that keep the program as VM bytecode and were not lifted: vmConstantsRecall(original, vm.constants), the share of the original’s string literals (two characters or more) that appear among the constants read from the script’s own decryptor, with none of the program run. A profile of the data, not a reconstruction. Mean over VM fixtures.
* **stability**: Wall-clock milliseconds of one recover() call (sandboxed evaluation on) on the reference machine; failures = fixtures whose recovery threw or whose output does not parse.

Status words: **verified** (every judged fixture of the configuration passes the gates), **partial** (some do), **experimental** (identified and measured, below the gates), **unsupported** (identified or detected, not recovered), **identification-only** (no fixtures, only a rule).
